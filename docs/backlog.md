## A. 所得控除の対象範囲(要方針決定)

現在エンジンが扱う所得控除は **社保・iDeCo・基礎・配偶者・配偶者特別・扶養・特定親族特別** のみ。以下は未実装で、**どこまで扱うかの線引きが未決**。

| 控除 | 必要なデータ | 備考 |
|---|---|---|
| 生命保険料控除 | `Person.deductions.lifeInsurancePremiumAnnual` は**既にあるが未実装** | 正の値は現在エンジンが明示的に拒否。新/旧制度で計算式が違う。最大12万円 |
| 地震保険料控除 | 新規 | 最大5万円 |
| 医療費控除 | 新規(年ごとの変動値) | 10万円 or 所得5%の足切り。年次で変動するのでイベント型が向く |
| 寄附金控除 | ふるさと納税は `furusato.ts` に限度額計算だけある | 控除自体は未反映 |
| 障害者控除・ひとり親控除・寡婦控除 | 世帯スキーマの拡張 | 調整控除の人的控除差もある |

**論点**: 生命保険料控除はフィールドだけ先に用意されている状態で、実装すれば即効く。まずこれだけ拾うか、「人的控除は一通り」まで広げるかで作業量が大きく変わる。

## B. 所得区分の拡張

給与所得のみ。自営業者と、正の `Person.retirementLumpSum` は現在エンジンが明示的に拒否する。

- 退職所得(退職所得控除・1/2課税・分離課税)
- 公的年金等(雑所得。老後フェーズの精度に直結)
- 不動産所得・事業所得

**論点**: 退職金は多くの世帯で数千万円規模になる。黙った過大評価は入力ガードで防いだが、該当世帯を計算できないため、モデル実装の**優先度は高い**。

### 資産取り崩し戦略

`household.savingsPolicy.drawdown.strategy` と戦略別の値はUIで入力できるが、現在の計算は資金不足額を `order` 順に取り崩すだけで、戦略と値は使用しない。UIには未使用であることを明示済み。

**論点**: `fixed-amount` / `fixed-rate` / `guardrail` を「不足額の補填」より先に行う定期取り崩しとして扱うか、既存の不足額補填ロジックを置き換えるかを設計書で決める必要がある。

## E. プロファイルの実行時検証

TypeScriptの型はコンパイル時だけで、localStorage・JSON読込・過去バージョンの保存データには効かない。現在は個別のフォーム検証と未実装入力ガードはあるが、プロファイル全体をエンジン境界で検証するスキーマはない。

- ゼロAPIキーで完結する実行時スキーマ検証を導入する
- スキーマバージョンと旧データのマイグレーション方針を決める
- 相互参照ID、年月の前後関係、重複IDなどの横断制約を境界で検証する

## 踏んだ罠(再発しやすいもの)

1. **`app/package-lock.json` の @emnapi ドリフト** — 3回発生。`npm install` は通るが `npm ci` だけが EUSAGE で落ちる。修正は `node_modules` と `package-lock.json` を消してクリーン再インストール。**Vite開発サーバーが起動しているとネイティブバイナリがロックされて削除に失敗する**ので先に止めること。app に依存を追加したら必ず `npm ci` で確認する(CIは npm ci を使う)

2. **合成DOMイベントによる誤診** — `input.focus()` + ネイティブsetter + `dispatchEvent` では React のイベントが期待どおり発火せず、**動いているコードを「壊れている」と誤判定した**。UIの挙動確認は `computer` ツールの実クリック・実入力で行う

3. **`gh run list --limit 1` が前回の実行を拾う** — push直後はまだ新しい実行が作成されておらず、古い成功を見て「CI通過」と誤判定する。**コミットのSHAで絞り込む**こと

4. **rebase後の重複コミット** — 別セッションやPR経由で同じ変更が先に取り込まれると、SHAが違うため「N件先行」に見える。`git diff origin/main main --stat` で**内容差分**を先に見る。`git pull --rebase` は patch-id 一致で自動的にスキップする

5. **要約モデル経由の一次情報は表の列を取り違える** — 江東区の調整控除の表で「差」列が「適用無」なのを取り違えかけた。**表の値が判断を左右する場合は生HTMLを直接読む**

6. **`exactOptionalPropertyTypes: true`** — optional プロパティに `undefined` を明示的に渡す箇所は `?: T | undefined` と書く必要がある
